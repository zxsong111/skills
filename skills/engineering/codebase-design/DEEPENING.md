# 加深（Deepening）

在给定依赖的情况下，如何安全地加深一组浅模块。默认你已掌握 [SKILL.md](SKILL.md) 中的词汇：**模块**（module）、**接口**（interface）、**接缝**（seam）、**适配器**（adapter）。

## 依赖类别

评估一个加深候选时，先给它的依赖分类。类别决定了加深后的模块如何跨接缝进行测试。

### 1. 进程内（In-process）

纯计算、内存状态、没有 I/O。总是可以加深：把模块合并，直接通过新接口测试。不需要适配器。

### 2. 可本地替代（Local-substitutable）

有本地测试替身的依赖（用 PGLite 替代 Postgres、内存文件系统）。只要替身存在就可以加深。加深后的模块在测试套件中搭配运行中的替身进行测试。接缝是内部的；模块的外部接口上没有端口（port）。

### 3. 远程但归自己所有（端口与适配器，Ports & Adapters）

跨网络边界的、你自己的服务（微服务、内部 API）。在接缝处定义一个**端口**（port，即接口）。深模块持有逻辑；传输层作为**适配器**注入。测试使用内存适配器。生产环境使用 HTTP/gRPC/队列适配器。

建议的表述形态：*「在接缝处定义一个端口，为生产环境实现一个 HTTP 适配器、为测试实现一个内存适配器，这样即使部署跨越网络，逻辑也待在同一个深模块里。」*

### 4. 真正的外部依赖（Mock）

你无法控制的第三方服务（Stripe、Twilio 等）。加深后的模块以注入端口的方式接收这个外部依赖；测试提供一个 mock 适配器。

## 接缝纪律

- **一个适配器意味着假想的接缝。两个适配器意味着真实的接缝。** 除非至少有两个适配器站得住脚（通常是生产 + 测试），否则不要引入端口。只有一个适配器的接缝只是多绕了一层。
- **内部接缝与外部接缝。** 一个深模块既可以有内部接缝（对其实现私有，供它自己的测试使用），也可以有位于其接口处的外部接缝。不要仅仅因为测试用到了内部接缝，就把它们通过接口暴露出去。

## 测试策略：替换，而不是叠加

- 一旦在加深后模块的接口上有了测试，浅模块上的旧单元测试就成了累赘；删掉它们。
- 在加深后模块的接口上编写新测试。**接口就是测试面**。
- 测试通过接口对可观察的结果做断言，而不是对内部状态做断言。
- 测试应该能挺过内部重构，因为它们描述的是行为，而不是实现。如果实现一变测试就得跟着改，那它就是在越过接口测试。
