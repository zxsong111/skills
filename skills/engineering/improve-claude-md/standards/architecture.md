# 目录结构与分层

**适用条件：** 有两个及以上模块 / 层的项目

**先探查：** `git ls-files` 得到的顶层结构；import 关系（谁导入谁）；生成代码目录（`gen/`、`__generated__`、`*.pb.go`）

## 待定项

逐项拍板；本项目不需要的写「不适用」。每项都写成可检查的句子。

| 项 | 要定什么 | 例子 |
|---|---|---|
| 目录职责 | 每个顶层目录用一句话说明放什么 | `src/domain/` 是纯业务逻辑，不依赖框架 |
| 依赖方向 | 明确写出谁不许导入谁 | `domain` 不许导入 `api` 或 `db` |
| 入口 | 程序入口、路由注册、DI 装配分别在哪 | `src/main.py` |
| 生成代码 | 哪些目录是生成的；绝不手改，改源头再重新生成 | `src/gen/**` 由 `make proto` 生成 |
| 新模块放哪 | 新功能的默认归属 | 每个业务领域一个 `src/<domain>/` |

## 落点

- 第 2 层：工具能强制依赖方向的就用工具（eslint `no-restricted-imports`、import-linter、ArchUnit）
- 第 1 层：生成代码目录以 `Edit(<dir>/**)` 的形式放进 `permissions.deny`（`Write(...)` 规则能被接受但不生效）
- 第 5 层：目录职责概览写进 CLAUDE.md「项目结构」，只写目录名看不出来的东西
