# Internationalization / localization

**Applies when:** Has a multilingual UI or serves users in multiple regions

**Probe first:** i18n library, where the copy resource files live, existing hardcoded strings

## Items to decide

Decide each item; write "not applicable" for any this project doesn't need. Phrase each one as a checkable sentence.

| Item | What to decide | Example |
|---|---|---|
| Externalized copy | UI copy goes in resource files; never hardcode it | none |
| Key naming | Layered by page / module | `checkout.button.pay` |
| Formatting | Numbers, dates, and currency use locale-aware APIs | `Intl.NumberFormat` |
| Adding a language | Fallback strategy for missing translations | Fall back to en |

## Where it lands

- Layer 2: hardcoded string detection (eslint-plugin-i18next and the like)
- Layer 3: `.claude/rules/i18n.md`, with `paths:` scoped to the UI directories
